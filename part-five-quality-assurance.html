Part Five · Quality Assurance

Each batch must be analyzed in QA before it can be added to the Data Registry. QA is not a guided question-and-answer workflow. It analyzes the batch, flags potentially problematic examples, and provides a clear written explanation for each flag.

Analyze a batch

  1. Run QA on the batch.
  2. Review each flagged example and its written explanation.
  3. Choose whether to regenerate flagged examples, remove them through Deduplicate, or leave the flags as they are.
  4. Approve or reject the batch.

Regenerate Flagged

Click Regenerate Flagged to automatically regenerate flagged examples. The regenerated examples are analyzed again.

Some examples may remain flagged or return to the flagged group if regeneration has not adequately addressed the issue. The user can click Regenerate Flagged repeatedly to continue the process, including until the score reaches 100% if desired.

Deduplicate

Click Deduplicate to instantly delete all flagged examples from the batch. Regenerate Flagged attempts to regenerate the examples; Deduplicate deletes the flagged examples.

Approve or reject

After QA analysis, the user must approve or reject the batch. Approved batches are added to the Data Registry.

The user may ignore any flags and approve the batch. A flag may not align with the user's intention for an example, so the user retains the final say on quality. The user may approve a batch with flags remaining and does not have to reach a 100% score first.
